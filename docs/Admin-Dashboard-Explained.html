Admin Dashboard — Settings Explained

Complete reference for every setting in the Admin and Monitoring dashboards. ADMIN :8443 MONITOR :8080

Architecture Overview

The bot has two separate dashboards serving different purposes:

Admin Dashboard

PORT 8443

Purpose: Configuration, secrets management, bot control

Access: HTTPS with HTTP Basic Auth

Location: src/admin/

Pages: Settings, Wallet & Secrets, Bot Control

Runs: Separately from the bot process

Monitoring Dashboard

PORT 8080

Purpose: Read-only live monitoring of bot performance

Access: HTTP with optional Basic Auth

Location: src/dashboard/

Pages: Single-page with live WebSocket updates

Runs: Embedded in the main bot process

1. Trading Parameters

Core trade execution settings that apply across all strategies.

SettingEnv VarTypeDefaultDescription
Order Size BOT_ORDER_SIZE float 250.0 Dollar amount per order for price-lag and arbitrage strategies. This is the target size — actual fill size depends on orderbook depth. Larger values mean more exposure per trade but also more potential profit.
Order Type BOT_ORDER_TYPE select FOK FOK (Fill or Kill): order must fill completely and immediately or is cancelled. GTC (Good Till Cancelled): order remains open until filled. FOK is safer for directional strategies; GTC is used by the asymmetric strategy for patient accumulation.
Target Pair Cost BOT_TARGET_PAIR_COST float 0.94 For pure arbitrage: the maximum combined YES + NO price at which buying both sides is profitable after fees. Must account for taker fee (~3.15% at 50/50 odds) and winner fee (2%). Lower = stricter but fewer opportunities.
Min Profit Margin BOT_MIN_PROFIT_MARGIN float 0.003 Minimum profit per share ($) required to take an arbitrage trade. Acts as a safety margin above break-even. At 0.003, a $250 order needs at least $0.75 expected profit.
Cooldown Seconds BOT_COOLDOWN_SECONDS float 2.0 Minimum seconds between scan cycles. Prevents excessive API calls and duplicate entries. Lower = more responsive but higher API usage. Must respect the 60 orders/min rate limit.

2. Strategy Toggles

Enable or disable individual trading strategies. Multiple strategies can run concurrently.

SettingEnv VarDefaultDescription
Arbitrage (A) BOT_ENABLE_ARBITRAGE true Pure fee-adjusted arbitrage. Buys both YES and NO when combined cost < target pair cost. Nearly impossible to profit at current Polymarket fee levels. Combined spreads consistently > $1.01 vs the $0.94 target.
Price-Lag (C) BOT_ENABLE_PRICE_LAG false Exploits the delay between Binance spot price moves and Polymarket odds updates. When BTC moves up on Binance but YES price hasn't adjusted yet, buys the underpriced side. Primary alpha source — generates most of the bot's profit through early exits on directional moves.
Asymmetric Entry (B) BOT_ENABLE_ASYMMETRIC false Patient accumulation strategy. Places GTC limit orders on both YES and NO at cheap prices, building a low-cost-basis position. Completes when combined average cost is below target. Slower but lower risk.
Maker Arbitrage BOT_ENABLE_MAKER_ARBITRAGE false Like pure arbitrage but uses limit orders (maker, 0% fee) instead of FOK (taker). Can profit at tighter spreads (~$0.985 combined) because there's no taker fee. Downside: fills are not guaranteed and orders can be partially filled.
Multi-Market Scanner (D) BOT_ENABLE_MULTI_MARKET false Scans multiple markets simultaneously and picks the best opportunity across all assets. Useful when running multiple assets (BTC, ETH, SOL, XRP) to concentrate capital on the highest-EV trade.
Resolution Sniper BOT_ENABLE_RESOLUTION_SNIPER false Enters positions in the final ~2 minutes of a market window when the outcome is highly predictable. Uses spot price momentum and volatility to estimate win probability. Small position sizes but high win rate when calibrated correctly.
Parallel Strategies BOT_ENABLE_PARALLEL_STRATEGIES false When enabled, executes the best opportunity from each strategy simultaneously. When disabled (default), only the single best opportunity across all strategies is executed per cycle. Parallel mode uses more capital but captures more opportunities.
Note: Arbitrage alone produces zero opportunities at current market conditions. You must enable at least price_lag or resolution_sniper for the bot to trade.

3. Price-Lag Parameters

Controls for the price-lag strategy — the primary profit driver. These determine when to enter, when to exit, and how aggressively to trade.

Entry Parameters

SettingEnv VarDefaultDescription
Spot Move Threshold BOT_SPOT_MOVE_THRESHOLD 0.0005 Minimum spot price movement (as a fraction) required to trigger a signal. At 0.0005, BTC at $97K needs a $48.50 move. Lower = more signals but more noise/false positives. Higher = fewer but higher-quality signals. Current production: 0.0015.
Spot Window Seconds BOT_SPOT_WINDOW_SECONDS 10 Lookback window (seconds) for measuring spot price movement. The strategy compares current price to the price N seconds ago. Shorter = more responsive to sudden moves. Longer = smoother but slower to react.
Odds Lag Threshold BOT_ODDS_LAG_THRESHOLD 0.01 Minimum discrepancy between the implied probability (from spot move) and Polymarket odds before entering. At 0.01, the market must be at least 1 cent mispriced. Higher = fewer but higher-conviction trades. Current production: 0.015.
Lag Confirmations BOT_LAG_CONFIRMATIONS 1 Number of consecutive scan cycles the signal must persist before entering. At 1, enters immediately. At 3 (with 2s cooldown), waits ~6 seconds of sustained signal. Higher = fewer whipsaw entries but may miss fast opportunities. Current production: 3.
Dead Zone Start BOT_LAG_ENTRY_DEAD_ZONE_START 30.0 Don't enter in the first N seconds after a market opens. Markets are chaotic at open with wide spreads and unreliable prices. 30 seconds lets the orderbook stabilize.
Dead Zone End BOT_LAG_ENTRY_DEAD_ZONE_END 15.0 Don't enter in the last N seconds before a market closes. Not enough time for the trade to play out, and the resolution sniper handles the end-of-window period instead.

Exit Parameters

How exits work: The exit check loop runs every 2 seconds and evaluates three independent conditions: stop-loss, take-profit, and time-based exit. The first condition to trigger causes an immediate FOK sell at market.
SettingEnv VarDefaultDescription
Stop Loss % BOT_STOP_LOSS_PCT 0.08 Exit when position P&L drops below this percentage. At 0.08 (8%), a $50 position exits at -$4. With time decay enabled: First third of window: base threshold (8%). Middle third: doubled (16%). Last third: disabled entirely. Current production: 0.15 (15%).
Take Profit % BOT_TAKE_PROFIT_PCT 0.15 Exit when position P&L exceeds this percentage. At 0.15 (15%), a $50 position exits at +$7.50. With time decay enabled: First third: base (15%). Middle third: doubled (30%). Last third: disabled (let winners run to resolution for full $1.00 payout). Current production: 0.25 (25%).
Time Exit Seconds BOT_TIME_EXIT_SECONDS 45.0 Exit all directional positions N seconds before the market closes, regardless of P&L. Acts as a safety net to avoid holding through resolution with uncertain outcomes. Exception: "Lottery ticket" positions (<5% of cost value) are held to resolution instead. Current production: 30.
Stop Loss Time Decay BOT_STOP_LOSS_TIME_DECAY true Do not disable. When enabled, the stop-loss threshold widens as the market ages (doubled in middle third, disabled in last third). This is critical because late-window prices are extremely volatile on 15-min markets — a temporary -15% dip often reverses before resolution. Disabling this kills recovery plays. (Experiment #2: disabled → 0 winners in 15 trades, reverted.)
Take Profit Time Decay BOT_TAKE_PROFIT_TIME_DECAY true When enabled, the take-profit threshold widens in the middle third (lets winners grow more) and is disabled in the last third (lets winners run to full $1.00 payout at resolution). Correct behavior for asymmetric payoff markets.
Stop Loss Confirmations BOT_STOP_LOSS_CONFIRMATIONS 3 Number of consecutive 2-second intervals the stop-loss must be breached before exiting. At 3, requires ~6 seconds of sustained loss. Prevents whipsaw exits on momentary price noise.
Cheap Contract Threshold BOT_STOP_LOSS_CHEAP_THRESHOLD 0.10 Skip stop-loss entirely for positions with average entry price below this value. Contracts bought at $0.05–$0.10 are treated as "lottery tickets" — the downside is minimal but the upside is a $1.00 payout. Not worth stopping out.

4. Asymmetric Entry Parameters

Controls for the patient accumulation strategy. Builds positions gradually with limit orders.

SettingEnv VarDefaultDescription
YES Cheap Threshold BOT_YES_CHEAP_THRESHOLD 0.42 Buy YES tokens when the ask price is below this level. Lower = more selective but fewer fills.
NO Cheap Threshold BOT_NO_CHEAP_THRESHOLD 0.42 Buy NO tokens when the ask price is below this level. Typically set equal to YES threshold for balanced accumulation.
Accumulation Size BOT_ACCUMULATION_SIZE 10.0 Number of shares per buy order. Small sizes allow gradual position building and better average prices. Too small increases order count and API usage.
Max Accumulation/Side BOT_MAX_ACCUMULATION_PER_SIDE 200.0 Maximum shares to accumulate on one side (YES or NO) before the strategy considers the position "complete." The hedge pair is then sought on the opposite side.
Target Avg Combined BOT_TARGET_AVG_COMBINED 0.90 Target combined average cost for YES + NO. The strategy aims to build a hedged position where the total cost basis is below this level, guaranteeing profit at resolution.
Stale Order Seconds BOT_STALE_ORDER_SECONDS 120.0 Cancel unfilled GTC orders after this many seconds. Prevents orders from lingering across market windows or at stale prices.

5. Maker Arbitrage Parameters

Controls for the zero-fee arbitrage strategy using limit orders.

SettingEnv VarDefaultDescription
Pair Cost Target BOT_MAKER_TARGET_PAIR_COST 0.985 Maximum combined YES + NO limit order cost for maker arb. Since maker orders have 0% fee, this target is much higher than the taker arb target ($0.94). At $0.985, the guaranteed profit is $0.015/share.
Price Offset BOT_MAKER_PRICE_OFFSET 0.01 Place limit orders this amount below the best ask. Ensures orders are maker (not taker) and sit in the book for fills. At 0.01, if best ask is $0.50, the limit order is at $0.49.
Pair Timeout BOT_MAKER_PAIR_TIMEOUT_SECONDS 180.0 Cancel unfilled pair orders after this many seconds. If only one leg fills and the other doesn't within the timeout, the partial fill is unwound to avoid unhedged exposure.
Max Pending Pairs BOT_MAKER_MAX_PENDING_PAIRS 5 Maximum number of concurrent maker arb attempts. More pairs = more chances for fills but also more capital tied up in pending orders.
Min Profit Margin BOT_MAKER_MIN_PROFIT_MARGIN 0.002 Minimum profit per share required. At 0.002, each share must yield at least $0.002 profit. Acts as a dust filter to avoid negligible-profit trades.

6. Resolution Sniper Parameters

Controls for the end-of-window sniper. Enters when the outcome is near-certain based on spot price analysis.

SettingEnv VarDefaultDescription
Order Size BOT_SNIPER_ORDER_SIZE 150.0 Total dollar size for sniper entries. Smaller than the main order size because sniper has less time for the trade to play out. Current production: 30.
Min Confidence BOT_SNIPER_MIN_CONFIDENCE 0.90 Minimum estimated win probability before entering. The sniper calculates probability from spot price distance to the open price, adjusted for remaining time and volatility. At 0.90, only enters when 90%+ confident. Higher = fewer trades but higher win rate. Current production: 0.92.
Window Seconds BOT_SNIPER_WINDOW_SECONDS 120.0 Activate the sniper this many seconds before market close. At 120, starts evaluating at T-2 minutes. Earlier activation = more time to find entries but lower confidence.
Hard Stop Seconds BOT_SNIPER_HARD_STOP_SECONDS 15.0 Stop placing new sniper entries this many seconds before close. Prevents entering too late when orderbook depth may be thin and execution risky.
Max Entry Price BOT_SNIPER_MAX_ENTRY_PRICE 0.97 Reject sniper entries above this price. At $0.97, a winning trade yields only $0.03/share minus fees. A single loss at $0.97 wipes ~30 wins. Lower = better risk/reward but fewer opportunities. Current production: 0.80.
Exit Confidence Floor BOT_SNIPER_EXIT_CONFIDENCE_FLOOR 0.0 Emergency exit if win probability drops below this level after entry. At 0.0, disabled (hold to resolution). Set to e.g. 0.50 to exit sniper positions that become 50/50 coin flips.
Vol Window Seconds BOT_SNIPER_VOL_WINDOW_SECONDS 600 Lookback window (seconds) for calculating spot price volatility. Used to estimate the probability of price reversal before resolution. 600s = 10 minutes of data.
Momentum Window BOT_SNIPER_MOMENTUM_WINDOW_SECONDS 30 Short lookback window for momentum calculation. Captures the very recent price direction to boost or reduce confidence.
Vol Floor BOT_SNIPER_VOL_FLOOR 0.001 Minimum volatility floor. If measured volatility is below this, use this value instead. Prevents division-by-zero and overly confident predictions during flat markets.

7. Markets

Which assets and intervals the bot monitors and trades.

SettingEnv VarDefaultDescription
Markets BOT_MARKETS BTC,ETH,SOL,XRP Comma-separated list of crypto assets to trade. Each asset gets its own 15-minute prediction market on Polymarket. More assets = more opportunities but more capital spread.
Market Intervals BOT_MARKET_INTERVALS 15m Market window duration. Currently only 15-minute markets are supported on Polymarket for these assets. Do not change unless new intervals become available.
Slug Override BOT_MARKET_SLUG_OVERRIDE empty Override automatic market slug discovery. Useful for testing with a specific market or when the Gamma API returns unexpected results. Leave empty for automatic detection.

8. Risk Limits

Position sizing and loss limits that protect against catastrophic drawdowns.

SettingEnv VarDefaultDescription
Max Entries/Market BOT_MAX_ENTRIES_PER_MARKET 2 Maximum directional entries allowed per market window. At 2, the bot can buy into the same market twice (e.g., averaging down). Resolution sniper overrides this to 3. Higher = more averaging but more exposure to a single outcome.
Max Position/Market BOT_MAX_POSITION_PER_MARKET 1000.0 Dollar cap on total position (investment) in a single market. Prevents concentration risk. At $1000 with $250 order size, allows 4 entries max. Current production: $750.
Max Total Position BOT_MAX_TOTAL_POSITION 5000.0 Dollar cap on total exposure across all markets combined. Acts as a global position limit. Should be set relative to your total capital (sim or real).
Max Daily Loss BOT_MAX_DAILY_LOSS 250.0 Daily loss limit that triggers the circuit breaker. When realized daily losses exceed this amount, all new trading is halted for 24 hours. Does not unwind existing positions. Current production: $1000.
Max Unhedged Exposure BOT_MAX_UNHEDGED_EXPOSURE 500.0 Dollar cap on total unhedged (directional) exposure. Hedged positions (both YES + NO) don't count. Limits the bot's directional risk at any given moment. Current production: $250.
Kelly Fraction BOT_KELLY_FRACTION 0.25 Fraction of the Kelly criterion used for position sizing. Full Kelly (1.0) is mathematically optimal but extremely volatile. Quarter Kelly (0.25) reduces variance at the cost of slower capital growth. The risk manager uses this to scale order sizes based on estimated win probability and payoff ratio.
Circuit Breaker: When daily losses exceed max_daily_loss, the circuit breaker activates for 24 hours. It persists across restarts (saved in DB). The breaker also triggers after 4 consecutive execution failures. Check the Risk Status panel on the monitoring dashboard to see if it's active.

9. Simulation

Paper trading mode for testing without real money.

SettingEnv VarDefaultDescription
Dry Run BOT_DRY_RUN true When enabled: The bot simulates all trades without submitting real orders to Polymarket. Uses the actual orderbook to simulate fills at realistic prices. All P&L is tracked in the sim balance. Always test with dry run before going live.
Sim Balance BOT_SIM_BALANCE 1000.0 Starting balance for simulation mode. All trades deduct from / add to this balance. The equity curve and daily snapshots track this value over time. Current production: $10,000.

10. Monitoring & Alerts

Notification settings for trade alerts and errors.

SettingEnv VarDefaultDescription
Telegram Chat ID BOT_TELEGRAM_CHAT_ID empty Your Telegram chat ID for receiving alerts. Use @userinfobot on Telegram to find your chat ID. Requires a Telegram bot token (set in Wallet page).
Alert on Trade BOT_ALERT_ON_TRADE false Send a Telegram/Discord notification every time a trade is executed. Can be noisy with active strategies. Best for low-frequency strategies or initial testing.
Alert on Error BOT_ALERT_ON_ERROR false Send a notification when errors occur (WebSocket disconnects, order failures, circuit breaker activation). Recommended for production to catch issues early.

11. Operational

Logging and system-level settings.

SettingEnv VarDefaultDescription
Log Level BOT_LOG_LEVEL INFO Logging verbosity. DEBUG: Everything including orderbook deltas (very noisy). INFO: Trade decisions, exits, market events (recommended). WARNING: Only problems and risk events. ERROR: Only failures.
Log Format BOT_LOG_FORMAT json json: Structured JSON logs, ideal for parsing and analysis with tools like jq. console: Human-readable colored output, better for watching logs in real time. Production should use json.
Neg Risk BOT_NEG_RISK true Must be true for BTC/ETH/SOL/XRP 15-minute markets on Polymarket. This is a Polymarket protocol requirement — neg_risk markets use a different order signing flow. Do not change.

13. Decision Logging

Observability settings for recording strategy decisions, spot prices, and daily summaries.

SettingEnv VarDefaultDescription
Decision Logging BOT_ENABLE_DECISION_LOGGING false Record every strategy evaluation to the strategy_decisions database table. Captures opportunities seen, risk rejections, and execution decisions. Essential for self-learning analysis. Enabled automatically when dashboard is enabled.
Spot Snapshot Interval BOT_SPOT_SNAPSHOT_INTERVAL 5.0 Save spot prices to the database every N seconds. Used for historical price lookups during outcome resolution and self-learning analysis. Lower = more precise but more DB writes.
Daily Summary Hour BOT_DAILY_SUMMARY_HOUR 0 UTC hour at which the daily performance snapshot is saved. At 0, the snapshot is taken at midnight UTC. The snapshot captures trades, P&L, win rate, fees, and drawdown for the day.

14. Wallet & Secrets Page

Manages encrypted secrets and wallet configuration. Accessible at /wallet on the admin dashboard.

Security: All secrets are stored in an AES-encrypted vault file (data/vault.enc). Private keys are write-only — they are never sent back to the browser after being saved. The admin dashboard uses HTTPS with auto-generated self-signed certificates.

Vault Management

ENCRYPTED
FeatureDescription
Initialize Vault Create a new empty encrypted vault. Required before storing any secrets. The vault password is set via the VAULT_PASSWORD environment variable.
Change Password Re-encrypt the vault with a new password. All existing secrets are preserved.
Vault Status Shows whether the vault is initialized, unlocked, and how many secrets are stored.

Secret Fields

WRITE-ONLY
SecretEnv VarDescription
Private Key BOT_PRIVATE_KEY Ethereum private key (0x...) for signing Polymarket orders. Write-only — displayed as "********" after saving. This key controls your trading wallet.
Funder Address BOT_FUNDER Polymarket proxy wallet address (Gnosis Safe). For Magic.link accounts (signature_type=1), this is the proxy wallet, NOT the signer address. Auto-detected via the Derive Wallet feature.
Telegram Bot Token BOT_TELEGRAM_BOT_TOKEN Token for the Telegram bot that sends alerts. Create a bot via @BotFather on Telegram to get this token.
Discord Webhook URL BOT_DISCORD_WEBHOOK_URL Webhook URL for Discord channel notifications. Create in Discord channel settings → Integrations → Webhooks.
Dashboard Password BOT_DASHBOARD_PASSWORD Password for the monitoring dashboard HTTP Basic Auth. Leave empty to disable auth on the monitoring dashboard.

Wallet Derivation

The Derive Wallet feature (/api/wallet/derive) performs these steps:

  1. Derives the Ethereum address from your private key
  2. Auto-detects signature type (EOA vs Gnosis Safe / Magic.link)
  3. Verifies the wallet against the Polymarket API
  4. Returns API key preview (first 12 characters)
  5. Stores the detected signature_type to .env

15. Bot Control Page

Start, stop, and restart the bot service. Accessible at /control on the admin dashboard.

ControlAPIDescription
Start Bot POST /api/bot/start Starts the 15minuteprofitable systemd service. Equivalent to systemctl start 15minuteprofitable.
Stop Bot POST /api/bot/stop Stops the bot service gracefully. Open positions are not unwound automatically — they will be held to resolution.
Restart Bot POST /api/bot/restart Restarts the bot service. Settings changes in .env take effect after restart. State (positions, daily P&L) is recovered from the database on startup.
Bot Status GET /api/bot/status Returns current status (active/inactive) and uptime. Displayed in the status card on the control page.
Note: The bot control page requires the admin dashboard to be running on the same server as the bot (uses systemctl directly). Settings changes via the Settings page require a bot restart to take effect.

16. Monitoring Dashboard — Overview Cards

The top section of the monitoring dashboard shows 6 live-updating summary cards (via WebSocket, every 3 seconds).

CardSourceDescription
Net P&L (Lifetime) /api/pnl Total cumulative profit/loss since the bot started tracking. Green if positive, red if negative. Sub-value shows today's P&L separately.
Total Trades WebSocket Count of all trades executed (filled orders). Includes all strategies.
Win Rate /api/metrics Percentage of trade results with positive net profit. Note: a low win rate (30–40%) can still be profitable with asymmetric payoffs.
Balance WebSocket Current simulation balance (in DRY_RUN mode) or USDC balance (in live mode). Updates with every trade result.
Exposure WebSocket Total dollar value of all open positions. Includes both hedged and unhedged positions.
Circuit Breaker WebSocket Shows OFF (normal) or ACTIVE (trading halted). Triggers on daily loss limit or consecutive failures.

17. Charts

Equity Curve (Line Chart)

Source: /api/equity-curve (up to 90 days)

Shows the sim balance over time as a line chart. Each data point is an end-of-day snapshot. The slope of this line is the bot's overall performance trajectory. A steady upward slope = consistent profits. Large drops indicate drawdown events.

Strategy Breakdown (Doughnut Chart)

Source: /api/strategies

Shows the proportion of trades by strategy as a doughnut chart. Helps visualize which strategy is generating the most activity. Colors: blue (arbitrage), green (price_lag), yellow (asymmetric), red (maker_arb), purple (sniper).
