Dynamic Allocation System: auto-rebalance based on rolling performance DEPLOYED

Hypothesis: Static allocations can't adapt to changing market conditions. A system that automatically shifts capital toward recently profitable strategies should improve overall P&L.

Implementation: New AllocationManager class (src/risk/allocation.py, 185 lines).

  • Metric: Exponential-decay-weighted profit factor (gross_wins / gross_losses) over 2-hour rolling window
  • Half-life: 30 minutes — recent trades weighted ~2x more than 30-min-old trades
  • Recalculation: Every 15 minutes (aligned with market cycles)
  • Multiplier bounds: 0.1x–3.0x of base size (floor prevents starvation, ceiling prevents over-concentration)
  • Cold start: Requires 5+ resolved trades per strategy before overriding static sizing
  • Integration: Hooks into main.py between opp.requested_size and RiskManager.adjust_size(). Risk manager still acts as absolute ceiling.

Files: src/risk/allocation.py (new), src/data/trade_db.py (+query), src/config.py (+flag), src/main.py (+wiring), tests/unit/test_allocation.py (18 tests, all passing)

5. Bregman Divergence / Information-Theoretic Framework

NEW FEB 8 Comprehensive mathematical framework integrated across all strategies. All features behind config toggles (default OFF). Zero behavior change unless explicitly enabled.

Why Bregman divergence? Ad-hoc confidence calculations treat probability space as Euclidean. A 5-cent mispricing at 0.50 is fundamentally different from 5-cent at 0.95, but Euclidean distance treats them the same. KL divergence (a Bregman divergence) correctly weights mispricings across the probability simplex.

Phase 1: Divergence Utility Module

IMPLEMENTED

File: src/utils/divergence.py (~150 lines) + tests/unit/test_divergence.py (~120 lines)

Pure math module with no side effects:

  • kl_divergence_binary(p, q) — D_KL(p||q) for binary distributions
  • simplex_project(yes_ask, no_ask) — Normalize to probability simplex (handles overround)
  • market_mispricing_score(yes_ask, no_ask) — Returns {p_fair, kl_divergence, kl_reverse, jensen_shannon, overround}
  • divergence_scaling_factor(kl) — Piecewise linear map for Kelly scaling (0.5x–2.0x)
  • compute_return_correlation(price_series, window) — Pearson correlation matrix from spot histories
  • bregman_projection(observed, correlation_matrix, n_iter) — KL projection onto correlation-consistent set
  • divergence_exit_signal(entry_kl, current_kl, direction, ratio) — Exit when mispricing has closed

Phase 2: Unified KL Mispricing Score

IMPLEMENTED (toggle OFF)

When enable_divergence_scoring=true:

  • All 7 strategies inject kl_* fields into opportunity metadata
  • Scanner uses composite ranking: alpha * profit_pct + (1-alpha) * kl_divergence
  • Higher KL = larger mispricing = higher priority in scanner ranking

Files modified: arbitrage.py, price_lag.py, dip_buyer.py, fade_panic.py, resolution_sniper.py, asymmetric.py, maker_arbitrage.py, scanner.py, main.py

Phase 3: Cross-Asset Correlation Strategy

IMPLEMENTED (toggle OFF)

File: src/strategy/cross_asset.py (~200 lines)

When enable_cross_asset_strategy=true:

  • Builds odds vector from orderbooks: [BTC_YES, ETH_YES, SOL_YES, XRP_YES]
  • Computes correlation matrix from historical spot data (refreshed every 15 min)
  • Bregman-projects odds onto correlation-consistent set (50 iterations)
  • Trades largest deviations where projected - observed > cross_asset_min_divergence
  • Holds to resolution (no early exit)

Architecture change: Added evaluate_all(markets) to BaseStrategy. Cross-asset overrides this to see all markets simultaneously. Scanner refactored to use evaluate_all() (existing strategies get default per-market fallback).

Phase 4: Divergence-Weighted Kelly Sizing

IMPLEMENTED (toggle OFF)

When divergence_kelly_scaling=true:

  • After computing base Kelly size, multiply by divergence_scaling_factor(kl)
  • Higher KL divergence → larger position (up to 2x). Lower KL → conservative (down to 0.5x)
  • Applied in risk/manager.py::kelly_adjusted_size()

Phase 5: Divergence-Based Exit Signals

IMPLEMENTED (toggle OFF)

When divergence_exit_signals=true:

  • Records entry KL divergence when opening a position (price_lag, dip_buyer)
  • On each should_exit() call, recomputes current KL
  • Exits when current_kl / entry_kl < divergence_exit_threshold (mispricing has closed)

6. New Strategies (Feb 8)

Dip Buyer / Mean Reversion

NEW

File: src/strategy/dip_buyer.py

Signal: Detects sharp spot price spikes/crashes (>0.15% in 3-5 seconds) that are likely overreactions, bets against them.

  • Spike UP → buy NO (expect reversion DOWN)
  • Crash DOWN → buy YES (expect reversion UP)
  • Must be an outlier: move >2x the rolling 60s average move

Exit logic: Time exit (60s before close), stop-loss (5%), take-profit (8%), divergence exit (optional).

Status: 0 trades so far — waiting for sufficient spot volatility. Strategy is evaluating correctly but hasn't seen a sharp enough move.

Fade Panic

NEW

File: src/strategy/fade_panic.py

Signal: In last 120 seconds of a market, detects when Polymarket odds shift >8% but spot price hasn't moved proportionally. This means someone is panic-buying/selling, creating mispricing.

  • YES odds spiked UP (panic buy) → buy NO (fade the panic)
  • YES odds crashed DOWN (panic sell) → buy YES (fade the panic)
  • Spot change must be <0.05% to confirm it's panic, not fundamental

Exit logic: Hold to resolution (same as sniper).

9. Strategy Insights

Patterns and insights discovered during the self-learning loop. These inform future strategy code changes (which require human approval before implementing).

Arbitrage alone produces zero opportunities

STRUCTURAL

Discovered: 2026-02-07 | Combined YES+NO prices $1.01-$1.05 vs $0.94 target. Pure arb is structurally unviable on Polymarket 15-min markets at current fee levels.

Early exits are the sole source of alpha

CRITICAL

Discovered: 2026-02-08 | Every dollar of profit comes from early exits. Held-to-resolution consistently loses (-$33 to -$51 avg). Exit tuning is higher priority than entry tuning.

Parallel strategies blocked by shared entry cap

RESOLVED

Discovered: 2026-02-08 | max_entries_per_market shared across all strategy types + sniper hardcoded override of 3 blocked fade_panic even at entry cap of 50. Fully resolved by removing sniper override and raising cap to 50.

Take-profit time decay was inverted

RESOLVED

Discovered: 2026-02-08 | TP time decay used * 2 (from SL), making it unreachable. Fixed to * 0.6.

Lottery ticket entries lose 100%

RESOLVED

Discovered: 2026-02-08 | Entries below $0.10 are deep OTM lottery tickets. When wrong, lose entire investment. Fixed with min_entry_price=0.10 across all strategies.

Server .env overrides code defaults silently

WATCH OUT

Discovered: 2026-02-08 (multiple times) | Pydantic's env_prefix="BOT_" means server .env values override code defaults without warning. Config changes in code are invisible unless .env is also updated. Examples: accumulation_size stuck at 10, order_size stuck at 100, resolution_sniper stuck at false.

Rule: After any config default change, ALWAYS check and update server .env.

BTC/ETH outperform SOL/XRP in directional strategies

INVESTIGATING

Discovered: 2026-02-09 overnight | In the same 15-min window, BTC asymmetric won +$110.54 and ETH won +$47.54, while SOL lost -$60.64 and XRP lost -$51.75. Consistent across multiple windows. SOL has the widest swings (biggest wins AND losses). Per-asset strategy parameters or filtering may improve overall edge.

Correlated 4-asset wipeout risk

INVESTIGATING

Discovered: 2026-02-09 00:27 UTC | All 4 markets lost simultaneously in window 1770596100 (-$259 total). Asymmetric picked the same direction on all assets. Since BTC/ETH/SOL/XRP are correlated, directional bets across all 4 amplify losses when wrong. Cross-asset correlation strategy (currently disabled) could detect and hedge this risk.

Win/loss sizes nearly equal — must achieve >50% WR to profit

CRITICAL

Discovered: 2026-02-09 overnight | Avg win $63.72, avg loss $64.47. At current sizing, the bot needs >50% win rate just to break even (before fees). Currently at 31% WR. Either win rate must improve dramatically, or wins must be made significantly larger than losses (asymmetric payoff).

Unhedged resolution is the #1 loss pattern

RESOLVED

Discovered: 2026-02-09 01:00 UTC | 54 unhedged trades held to resolution lost -$2,970 total. This single pattern causes 7.5x more losses than the bot's total P&L. Fixed by: (1) asymmetric hedged-only mode, (2) always-exit-unhedged logic, (3) reduced max_accumulation_per_side from 200 to 50.

Static allocation doesn't adapt to market conditions

RESOLVED

Discovered: 2026-02-09 01:00 UTC | All strategies had similar order sizes regardless of performance. Fade panic (+$216) had same base size as sniper (-$8). Dynamic allocation system deployed to auto-rebalance based on rolling 2-hour profit factor with exponential decay.

Memory grows ~7 MB per 15 minutes

MONITORING

Discovered: 2026-02-09 overnight | Memory grew 131→138→145 MB over 30 minutes before an auto-restart at 00:50 UTC reset it to 72 MB. Growth rate is ~7 MB per 15 min (~28 MB/hour). At this rate, the 3.7 GB server can run for days, but a slow memory leak may exist. Systemd auto-restarts mitigate the risk.
