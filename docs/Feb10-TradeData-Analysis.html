8. Trade Stacking Problem

The bot fires 5-12 entries per market window per strategy

This is the #1 risk amplifier. All entries in a window resolve to the same binary outcome, so stacking multiplies exposure without diversification.

Examples of Rapid-Fire Entry Stacking

WindowStrategyAssetEntriesTime SpanTotal InvestmentOutcome

09:59fade_panicBTC8 trades14 seconds$6.00 All lost (-$6.00)

Impact Analysis

  • 325 entries → 113 results: ratio of 2.88 entries per resolved outcome.
  • fade_panic: 183 entries → 39 results = 4.7 entries/result. Each "bet" is actually 5 bets.
  • When wrong, losses multiply: The 12-entry ETH fade at 06:13 lost $19.50 instead of $1.63 (single entry).
  • When right, wins also multiply: The 9-entry ETH fade at 09:28 won $195.43 instead of ~$22.
  • Net effect is negative: Amplification hurts more than it helps because the bot already has edge — it doesn't need leverage, it needs consistency.
RECOMMENDATION: Cap entries to 2-3 per strategy per 15-minute market window. This reduces variance without eliminating edge. A fade_panic trade that would win $14 as a single entry doesn't need to be $70 via 5x stacking.
